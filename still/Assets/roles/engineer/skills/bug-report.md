## When
The user found a bug, or describes something broken that needs writing up.

## Inputs
- What the user saw, where, and what they expected.
- Your conventions, for the report format, and Known bugs, to avoid duplicates.

## Steps
1. Check Known bugs for the same problem.
2. Reproduce it yourself in a tab when you can, and say whether you could.
3. Write a one-line title, what happened, what should happen, numbered steps, where (browser, page, account type) and how bad it is.
4. Add it to Known bugs with update_knowledge.

## Check
- Someone who wasn't there could follow the steps.
- The report says whether you reproduced it.

## Deliverable
The report in the format of Your conventions, or the one above, in Markdown. Filing it in a connected app waits for the user's OK.

## If it goes wrong
- You can't reproduce it: write it up with the user's steps and mark it not reproduced.
- It needs a sign-in you don't have: ask the user to sign in in the tab, or write it from their steps.

## Limits
Never guess the cause and present it as fact. Never submit forms that buy, send or delete while reproducing.
